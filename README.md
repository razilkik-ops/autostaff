# SGCB Russia

Полноценный интернет-магазин профессиональных товаров для детейлинга на Node.js, Express, EJS, PostgreSQL и Prisma.

## Что работает

- каталог, категории, карточки товаров, корзина и оформление заказа;
- серверный пересчёт цены и транзакционное списание остатков;
- отправка новых заказов в Telegram при заданных переменных окружения;
- регистрация и вход, безопасное хеширование паролей, серверные сессии;
- персональные лайки и комментарии зарегистрированных пользователей;
- блог и новости с SEO-описаниями, Schema.org, изображениями, видео, товарами из статьи и похожими материалами;
- подписка по e-mail;
- закрытая админ-панель для каталога, категорий, статей, новостей, комментариев и заказов.

## Стек

- Node.js 22+
- Express 5 и EJS
- PostgreSQL 14+
- Prisma ORM 6
- Vanilla JavaScript в браузере

## Локальный запуск

1. Установите зависимости:

   ```bash
   npm install
   ```

2. Скопируйте `.env.example` в `.env` и укажите PostgreSQL, секрет сессии и данные первого администратора.

3. Подготовьте базу:

   ```bash
   npm run db:migrate
   npm run db:seed
   ```

4. Запустите приложение:

   ```bash
   npm run dev
   ```

Сайт откроется по адресу `http://localhost:4174`, админ-панель — `http://localhost:4174/admin`.

## Проверка

Интеграционный тест использует PostgreSQL из `DATABASE_URL`, создаёт временные данные и удаляет их после выполнения:

```bash
npm run build
npm run check
```

Проверяются регистрация, хеширование пароля, сессия, лайки, комментарии, серверная цена заказа, списание остатка и разграничение доступа в админку.

## Переменные окружения

- `DATABASE_URL` — строка подключения к PostgreSQL.
- `SESSION_SECRET` — случайная строка длиной не меньше 32 символов в production.
- `APP_URL` — публичный адрес приложения.
- `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NAME` — администратор, создаваемый командой `npm run db:seed`.
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — необязательная отправка заказов в Telegram.

Секреты хранятся только в `.env` или в настройках хостинга. Файл `.env` исключён из Git.

## Развёртывание

GitHub Pages не запускает Node.js и PostgreSQL, поэтому новая серверная версия должна размещаться на хостинге с Node.js и постоянной PostgreSQL-базой (например, Railway, Render, Fly.io или VPS). Перед стартом production-процесса выполните:

```bash
npm ci
npm run build
npm run db:migrate
npm start
```

Текущий workflow GitHub выполняет сборку, миграции, seed и интеграционные тесты в изолированном PostgreSQL-контейнере; он больше не публикует несовместимую серверную версию в GitHub Pages.
